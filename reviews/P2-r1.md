## Findings

### HB-P2-r1-C1 (correctness, major): the egress table has no seam, fixture or red test

- Evidence: `SPEC.md:32` makes "Network egress capture" secondary table 3. `contracts/audit.rules.template:14-15` records `connect`, and `contracts/results.md:29` defines an `egress` row with `connects` and `named`. But `contracts/api.md` has no function that reads a `connect` record or joins it with monitor events, `parseAuditLog`'s Event has no socket address field, `fixtures/audit/basic.log` has one `connect` event (serial 527) with no `SOCKADDR` record, and `grep -i "egress\|connect" tests/red/*.mjs` returns nothing. No P3 lane owns this table, so P5 would have no tested code for it.
- Also missing from the contract: Node and curl connect non-blocking, so a successful TCP connect is often logged `success=no exit=-115` (EINPROGRESS); and under the box's boundary most connects go to 127.0.0.1. Without a rule for both, `connects` is undefined.
- Fix: a `Connect records` section in `contracts/truth.md` (SOCKADDR decoding for AF_INET and AF_INET6, classes `egress`, `loopback` and `failed`, EINPROGRESS counted as an attempt, exclusions as for writes); `collectConnects(text, context)` for P3b and `matchEgress(connectRecords, rawEvents)` for P3c in `contracts/api.md`; an egress section in `contracts/monitor.md` (literal address match through `server.address` and URL or `host:port` words; hostnames counted, not resolved); `saddr` on the parsed Event; the `egress` row's fields in `contracts/results.md`; fixtures `audit/connect.log` and `monitor/connect.runtime.jsonl` with expected files; stubs; red tests P3b-connect-* and P3c-egress-*; a contract test that the two connect fixtures agree.

### HB-P2-r1-S1 (security, medium): nothing stops a run as root, and three frozen scenarios then write the box's real `/etc/hosts`

- Evidence: `fixtures/scenarios/dev/hosts-program.json:14` runs `printf ... >> /etc/hosts`; `hosts-edit` (dev) and `hosts-shell` (heldout) target the same file. The design relies on that write being refused (`contracts/scenario.md:34`, `contracts/monitor.md:56`, DECISIONS.md "failures go to a `denied` column"). But no contract says the run user is not root: `contracts/run.md` has no run-user section, and `contracts/api.md:41` lets `renderRules` accept any non-negative integer, so `uid: 0` renders a valid rule set. A runner started as root would append to the box's `/etc/hosts`, and the `hosts` rows would change meaning without any test failing.
- Fix: a `Run user` section in `contracts/run.md` (never uid 0; the P4 runner refuses euid 0 before any setup); `renderRules` refuses uid 0 with `renderRules: uid 0 (root) is refused` (`contracts/api.md`); red test P3b-rules-root. The scenario files stay as they are, so the frozen split hash does not change.

### HB-P2-r1-C2 (correctness, minor): the staged upstream patch has no red test

- Evidence: `SPEC.md:44` lists it as a component; `upstream/README.md` only plans it; no manifest entry names it.
- Not fixed in round 2. A red test needs a stub that throws `HB not implemented`, and the deliverable is a patch against another repo, not a seam here. P3a's review checks the patch and its overlap note against SPEC.md:44.

### HB-P2-r1-D1 (docs, nit): vendor names in `models.lock`

- Evidence: `models.lock:10-12,16` hold the npm scopes of the three harness vendors and the monitor's GitHub owner. The standing constraint keeps company names out of repo names, package names, flags and UI chrome; these are third-party install identifiers in a data file, which the constraint does not name. Not a number. Left open; no change.
