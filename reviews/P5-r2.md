## Findings

### HB-P5-r2-E1 (eval validity, major): in the srt column the runner records namespace pids, so the ground-truth tree is empty

Evidence:
- r2 moved every stage into the srt column (`scripts/eval.sh`, `FORGE_COLUMN=srt`). forge's `sandbox/run-eval.sh` `run_column_srt` runs `derm run --boundary srt ... -- bash -c "$cmd"`. srt always passes `--unshare-pid` to bubblewrap (`@anthropic-ai/sandbox-runtime/dist/sandbox/linux-sandbox-utils.js` line 3039, `bwrapArgs.push('--unshare-pid')`, "By default, always unshare PID namespace").
- `src/run/runner.mjs` (head) writes `root_pid: result.pid` (`child.pid`) and `model_server_pids: [process.pid]` into `run.json`. `src/truth/collect.mjs` `walkTree` seeds the tree with `ctx.root_pid` and matches the `pid=`/`ppid=` of audit records. contracts/truth.md line 16 defines the tree from `root_pid`.
- auditd logs pids in the initial namespace. Run on this host with derm's bwrap: `bwrap --unshare-user --unshare-pid --bind / / --dev /dev --proc /proc -- node -e '<spawn /usr/bin/true hbmark, cwd /tmp/hbns-gSaDwi>'` printed `ns child.pid=9 ns process.pid=2`. The audit record for that execve (`audit(1795572288.253:5137064)`) says `ppid=1328266 pid=1328280`, `a0="/usr/bin/true" a1="hbmark"`, `cwd="/tmp/hbns-gSaDwi"`.
- So the tree holds pid 9 and the server pid 2. No record of the harness is in it, and every scored run has an empty truth set: the denominator is 0, or it holds an unrelated host process that happens to have that pid. This is new in r2: r1's landrun pass had no pid namespace.

Fix (applied in round 3): `src/run/runner.mjs` exports `hostPids()`. After the slice is read, the runner takes the first successful `execve`/`execveat` in the slice whose CWD is the harness's cwd (the run's own workspace) and whose argv holds the harness's argv[0]. That record's `pid` becomes `root_pid` and its `ppid` the model-server pid, and `run.json` is rewritten. `runOnce` returns `rootPidFrom` (`child`, `audit`, `audit_translated`, `unanchored`). `eval.mjs` writes it on every run row as `root_pid_from` and drops `unanchored` runs from bands, where they are named, as with rotated windows. contracts/run.md states it. Tests: `tests/integration/p5-hostpid.test.mjs`. The first test shows the bug: namespace pids give 0 writes for a harness write that is in the log. Checked live on this host with the real `runOnce` and audit log:
- outside a namespace, 6 of 6 runs gave `audit` with the same pids;
- inside `bwrap --unshare-pid`, 3 of 3 gave `audit_translated`, e.g. `{"self":2,"root":1336537,"server":[1336529]}`.

The match uses the slice's one-second margin, not `[start, end]`. A first version used the exact window and missed 3 of 6 runs, because the kernel's coarse audit clock stamped the root's execve a few ms before `start`.

Not verified here (needs the box): the same match inside `derm run --boundary srt` as forge-runner. srt could not start a nested sandbox from this session (`apply-seccomp: ... Permission denied`), so the check used derm's bwrap directly with the same `--unshare-pid`.

### HB-P5-r2-C1 (correctness, minor): `eval.sh` links into a real `node_modules` folder

Evidence: head `scripts/eval.sh`: `[[ -L node_modules ]] && rm node_modules; ln -s "$deps/node_modules" node_modules`. When `node_modules` is a folder without `derm-workspace` (a partial install), `ln -s` creates `node_modules/node_modules`. The eval then dies at import with the r1 C1 error and not the exit 3 that names the fix.

Fix (applied): such a folder exits 3 with a message. Test in `tests/integration/p5-eval-sh.test.mjs`: it fails on the r2 `eval.sh` (3 pass, 1 fail) and passes here (4 / 4).
