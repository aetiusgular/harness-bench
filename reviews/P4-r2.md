## Findings

### HB-P4-r2-E1 (eval validity, minor): combined short options ending in `o`, and `--opt=value`, still stop the nested-shell split

- **Evidence:** `src/score/words.mjs` lines 172 to 176 skip the `-o` argument only when the word is exactly `-o`/`+o`/`-O`/`+O`, and the long-option pattern `--[a-z][a-z-]*` does not match `=`. Probe:
  - `bash -euo pipefail -c "echo x > /tmp/a"` gives `["/w/echo x > /tmp/a"]` (want `["/tmp/a"]`). `-euo pipefail` is a common wrapper.
  - `bash --rcfile=/etc/rc -c "echo x > /tmp/a"` gives `["/etc/rc","/w/echo x > /tmp/a"]`.
  The effect is the same as round 1's E1: a monitor finding for that command does not match the real write, so the monitor's rate reads low. Minor because no frozen scenario's scripted command uses these forms (the integration run on all 12 dev scenarios passes), so it only matters for commands a harness writes itself.
- **Fix:** when a short option word ends in `o` or `O`, skip the next word too; accept `--[a-z][a-z-]*(=.*)?` as one option word. Add both lines to the HB-P4-r1-E1 test in `tests/integration/p4-contract.test.mjs`. Can go with P5's tuning on dev.

### HB-P4-r2-D1 (docs/tests, nit): the setsid runner test leaves a `sleep 30` running

- **Evidence:** after `node --test --test-name-pattern='HB-P4-r1-C1' tests/integration/runner.test.mjs`, `ps -o pid,ppid,pgid,sid,etimes,cmd` showed `1117225 1 1117225 1117225 13 sleep 30`. This is the behaviour the test checks for (the run does not wait on it), but every ci run leaves a 30 s process behind.
- **Fix:** use `setsid sleep 3` in the stand-in CLI; the test still proves the run returns before the orphan ends.

## Not findings

- The live rows (`results/p4-live-runner.jsonl`, `git_sha` `beff174`) predate the `detached` spawn. `detached` also starts a new session, so the CLI has no controlling terminal. The sessions that run here already have none: `/dev/tty` from this session's shell gives `ENXIO` and `ps` shows tty `?`. So the change takes away nothing the live runs had. The rows record their own sha, and the PR body says they were not run again. P5 runs the real CLIs again on the box.
- A process that leaves the group survives the run, as the account the run uses. The collector attributes writes through the process tree from `root_pid` (`src/truth/collect.mjs` lines 54 to 66), so an orphan from one run is not counted in the next run's truth. SECURITY.md and DECISIONS.md say that writes after `end` fall outside the window.
- `end` is now taken up to 2 s after the harness exits when an orphan holds the pipes. That widens the window by at most the grace period, and only inside the run's own process tree.
